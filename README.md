# 마이바디 — 내 몸 관리 PWA

**배포됨** — 앱 <https://mio-modu.github.io/mybody_management/> · 소개 페이지 <https://mio-modu.github.io/mybody_management/landing/>
(기본 브랜치에 푸시하면 자동으로 다시 배포된다.)

체중 **68kg**, 혈당, 콜레스테롤, 그리고 **목·허리 통증**을 한 화면에서 관리하는 개인용 PWA.
설치형 앱스토어 배포가 아니라, 내 폰 홈 화면에 올려놓고 쓰는 개인 도구다.

- 빌드 도구·패키지·서버 없음. 정적 파일만으로 동작한다.
- 모든 기록은 **내 브라우저 안(localStorage)** 에만 저장된다. 서버로 전송되지 않는다.
- 오프라인에서도 열리고 기록된다(Service Worker).

---

## 핵심 설계: 묻고 → 판단하고 → 조절한다

기능을 늘리는 대신, 매일 반복되는 이 루프 하나만 정확히 돌아가게 만들었다.

| 단계 | 어디서 | 하는 일 |
|---|---|---|
| **묻는다** | 홈 화면 "체크인" | 지금 시간대에 아직 답하지 않은 2~4개만 묻는다. 아침엔 체중·공복혈당·목/허리, 낮엔 식후혈당·앉은 시간, 저녁엔 통증·처방 운동·걸음 |
| **판단한다** | 통증 화면 | NRS 0~10 점수를 4단계(강화 / 가동성 / 진정 / 보호)로 나누고, 최근 3회 평균이 올라가는 중이면 **자동으로 한 단계 낮춘다** |
| **조절한다** | 오늘의 처방 | 그 단계에 맞는 운동·횟수·이유가 바로 나온다. 유발 요인(앉은 시간, 모니터, 수면 자세…)에 맞춘 "오늘 바꿀 것"도 함께 |

적색신호(팔다리 저림/힘빠짐, 대소변 장애, 발열, 외상, 야간통)를 체크하면 운동 처방 대신
**진료를 먼저 보라는 경고**를 띄운다. 자가 운동으로 다룰 범위를 넘는 신호이기 때문이다.

## 여러 사람이 쓸 수 있다

처음 열면 **1분 온보딩**이 뜬다. 이름·키·목표 체중을 받고, 무엇을 관리할지 고르게 한다.

- **관리 모듈** — 체중(기본) / 혈당 / 혈액검사·혈압 / 통증. **끈 모듈은 탭·체크인·미션·리포트에서 통째로 사라진다**
- **아픈 곳** — 목·허리·어깨/등·무릎 중 선택. 고른 부위만 묻고, 부위별로 처방이 따로 나온다
- **프로필** — 설정에서 추가하면 한 기기에서 여러 명이 각자 쓴다. 목표·기록·포인트가 완전히 분리된다

혈당을 끄면 혈당 탭이 사라지고, 오늘의 미션도 그에 맞게 바뀐다. 쓰지 않는 기능이 자리를 차지하지 않는다.

> 제품으로 키울 때의 단계·수익·의료 경계선·측정 지표는 **[PRODUCT.md](./PRODUCT.md)** 에 정리했다.

## 입력이 귀찮지 않게

기록 앱이 죽는 가장 큰 이유는 입력 마찰이다. 가장 귀찮은 두 가지를 먼저 없앴다.

**검진 결과지 → 붙여넣기 한 번.** 문자·앱·PDF에서 결과를 복사해 붙여넣으면 14개 항목과 검사일이
자동으로 채워진다. 병원마다 다른 표기(`LDL-콜레스테롤` / `LDL-C` / `저밀도지단백`)를 전부 알아듣고,
`(0~130)` 같은 참고범위나 `<200` 같은 기준치는 걸러낸다. 못 읽은 항목만 직접 치면 된다.

**종이 결과지뿐이라면** 사진을 띄워 놓고 입력한다. 사진은 화면에 보이기만 할 뿐
앱에 저장되지도, 어디로 전송되지도 않는다.

> 통증 점수만은 끝까지 손입력으로 남겼다. 센서가 못 재고, 그날 몸을 한 번 돌아보게 만드는 것 자체가 기능이다.

## 병원에 들고 갈 한 장

리포트 → **진료용 요약 1장**. 최근 90일을 A4 한 장으로 정리한다.

- 체중 — 시작 → 현재(7일 평균) → 목표, 30일 변화, BMI, 허리둘레
- 혈당 — 측정 시점별 횟수·평균·최저~최고·목표 범위 내 비율, 추정 당화혈색소
- 검사 — 최근/이전 2회 비교와 변화량, 중성지방/HDL 비
- 통증 — 부위별 7일·30일 평균과 최고, 내가 꼽은 유발 요인, **적색신호를 체크한 날**
- 추세 그래프 2개, 복약·참고 사항

판정하거나 진단하는 문장은 한 줄도 쓰지 않는다. 마지막 줄에 "사용자가 직접 입력한 값이며
판독은 진료하시는 분께 맡긴다"고 적어 둔다. 인쇄 화면에서 PDF로 저장하면 그대로 보낼 수 있다.

## 보상 — 매일 미션을 해내면 나에게 돌아오는 것

**오늘의 미션 3개**만 채우면 그날은 성공이다. 루틴 9개를 다 할 필요 없다.

1. 몸 상태 한 번 기록 (고른 부위 점수 1회)
2. 루틴 5개 이상 체크
3. 숫자 1개 이상 (체중 또는 혈당)

통증 관리를 꺼 두면 1번이 빠지고 "움직임 기록(걸음·물)"이 들어간다. 미션은 항상 3개다.

| 규칙 | 값 |
|---|---|
| 미션 3개 달성한 하루 | **+10p** |
| 연속 7일마다 | **+30p 보너스** |
| 포인트로 바꾸는 것 | 설정에 내가 직접 적어둔 **실제 보상** (디저트·영화·마사지…) |

**포인트는 체중이나 혈당 수치에 걸지 않는다.** 기록과 루틴 — 내가 통제할 수 있는 행동에만 건다.
수치는 수면·생리주기·소금 섭취에 따라 흔들리므로, 거기에 보상을 걸면 과속하거나 일찍 포기하게 된다.
숫자가 나쁜 날에도 기록만 하면 그날은 성공이다.

리포트 화면에 **연속일 · 4주 스탬프 · 뱃지 12종**이 있고, 홈 맨 위에 오늘 미션 링이 있다.
뱃지는 결과(−1kg, 목표 도달, 혈당 안정)도 축하하지만 포인트로는 바뀌지 않는다.

> 보상은 **실제로 받아야** 작동한다. 포인트만 쌓고 넘어가면 다음 주부터 미션이 의미를 잃는다.

## 디자인

시각 유형 **T13 소프트 3D 정물** (`mio-modu/Webdesign_style` 카탈로그)을 적용했다.
개인 도구로 재도, 제품으로 재도 25개 중 1위였다(23.9점 / 2위 12.4점).

지면에 따라 가져오는 범위가 다르다.

| 지면 | 가져온 것 |
|---|---|
| **앱 화면** (`/`) | 매일 오래 쓰는 화면은 카탈로그의 범위 밖이라, 규칙대로 **팔레트 7토큰 · 대비 4.5 게이트 · reduced-motion 처리만** |
| **랜딩** (`/landing`) | 범위 안이므로 **구도·입체·이미지 명세까지 전부** — 무광 3D 정물 3개, 비정삼각 배치, 높이차 8:5:3 |

선정 이유, 토큰 표, 차트 계열색, 안티패턴, 랜딩 판정 문장 통과 여부, 브라우저 검증 결과는
**[DESIGN.md](./DESIGN.md)** 에 있다. 다른 디자이너나 AI에게 그대로 넘길 수 있게 쓴 문서다.

## 설치해서 쓰기

### 1. 어딘가에 올린다 (셋 중 하나)

**GitHub Pages — 이미 배포되어 있다**

`.github/workflows/pages.yml` 이 기본 브랜치에 푸시될 때마다 앱과 소개 페이지를 함께 올린다.
처음 한 번만 사람이 켜 줘야 했고(그 작업은 끝났다), 그 뒤로는 손댈 것이 없다.

> 이 저장소를 복제해 처음부터 올린다면 두 가지가 필요하다.
> **저장소가 Public** 이어야 하고(무료 플랜에서 Private 저장소는 Pages 가 막혀 있다),
> **Settings → Pages → Source** 를 `GitHub Actions` 로 한 번 바꿔 줘야 한다.
> Actions 기본 토큰에는 Pages 사이트를 처음 만드는 권한이 없어 이것만은 자동화가 안 된다.

| | 주소 |
|---|---|
| 앱 | `https://mio-modu.github.io/mybody_management/` |
| 소개 페이지 (남에게 보낼 주소) | `https://mio-modu.github.io/mybody_management/landing/` |

그 다음부터는 푸시할 때마다 자동으로 다시 배포된다.

**내 컴퓨터에서만**
```bash
python3 -m http.server 8765
# http://localhost:8765 접속
```
> `file://` 로 직접 열면 ES 모듈과 Service Worker가 막힌다. 꼭 http로 열 것.

### 2. 홈 화면에 추가

- **iPhone (Safari)**: 공유 버튼 → `홈 화면에 추가`
- **Android (Chrome)**: 메뉴 → `앱 설치` 또는 `홈 화면에 추가`

남에게 보낼 때는 설정 → **공유 → 소개 링크 보내기**. 메신저에 파일로 보내야 한다면
`landing/index.single.html` 한 장을 보낸다(색과 이미지가 파일 안에 들어 있어 혼자 열어도 그대로 보인다).

추가하면 주소창 없는 전체 화면 앱으로 뜨고, 오프라인에서도 열린다.

## 처음 1분 세팅

앱을 처음 열면 온보딩이 안내한다 — 이름·키·지금 체중·목표 체중, 관리할 모듈, 아픈 곳.
그 다음 두 가지만 더 하면 끝이다.

1. 검사 화면에 **가장 최근 건강검진 숫자**를 한 번 넣기 (여기가 출발 좌표가 된다)
2. 통증 화면에서 점수 한 번 기록 → 바로 오늘의 처방이 생긴다

그 다음부터는 홈 화면 체크인만 따라가면 된다. 목표치는 설정에서 언제든 바꾼다.

## 알림에 대한 솔직한 설명

서버 없는 PWA라서 **앱이 열려 있는 동안에만** 알림이 뜬다(설정에서 시각 지정 + 권한 허용).
확실히 챙기려면 **휴대폰 기본 알람을 아침·낮·저녁 시각에 맞춰두고, 알람이 울리면 앱을 열어** 체크인하는 방식이 낫다.
홈 화면 아이콘을 길게 누르면 통증/혈당/체중 기록으로 바로 가는 바로가기도 있다.

## 내 몸에 맞게 고치기

거의 모든 개인화는 `js/config.js` 한 파일에 모여 있다.

| 바꾸고 싶은 것 | 위치 |
|---|---|
| 목표 수치 기본값 | `DEFAULT_TARGETS` (설정 화면에서도 변경 가능) |
| 통증 부위 추가/삭제 | `PAIN_AREAS` |
| 단계별 운동 처방 | `PROTOCOLS` (부위 × 단계 A/B/C/D) |
| 통증 유발 요인 목록 | `PAIN_TRIGGERS` |
| 매일 루틴 체크리스트 | `ROUTINE` |
| 혈액검사 항목·정상 기준 | `LAB_FIELDS` |
| 오늘의 미션 3개 | `coreMissions()` |
| 관리 모듈 | `MODULES` (앱 온보딩·설정에서도 선택) |
| 포인트 적립량·보너스 | `POINTS` |
| 보상 목록 기본값 | `DEFAULT_REWARDS` (앱 설정에서도 편집 가능) |
| 뱃지 종류 | `BADGES` + `js/rewards.js` 의 `badgeList()` |
| 시간대별로 묻는 항목 | `CHECKIN_SLOTS` + `js/checkin.js` |
